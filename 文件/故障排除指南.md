# 故障排除指南

> 比賽或測試時遇到問題？找這份文件就對了。

---

## 🤖 取物機器人（八足 Theo Jansen）

### 無線通訊相關（ESP-NOW / 藍芽）

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| 手機找不到 ESP32 | 藍芽未開啟 | 確認 ESP32 程式中已初始化 |
| 藍芽斷線 | App 重新連線 | 如果連不上就重啟 ESP32 |
| App 連線後馬達不動 | ESP-NOW 未正確配對 | 確認 MAC 位址正確、ESP-NOW 已初始化 |
| 連線後偶爾斷線 | 電池電壓低 / 距離太遠 | 充電、靠近（ESP-NOW 有效距離約 200m） |
| ESP32 C3 子控板無回應 | ESP-NOW 配對失敗 | 重新寫入程式、確認雙方 MAC 位址 |
| iOS 無法使用 | ESP32 BLE 需專用 App | 使用專用遙控 App 或改用 Android |

### 馬達相關

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| 馬達完全不轉 | 接線錯誤 / BTS7960 R_EN 未接 3.3V | 檢查接線圖、**確認 R_EN/L_EN 已接 3.3V** |
| 馬達方向反了 | M+/M- 接反 | 交換 BTS7960 M+/M- 的接線，或修改程式碼 |
| 前進時機器人歪斜 | 左右馬達速度不同 | 調整 PWM 速度或在程式中加左右補償 |
| 伺服馬達抖動 | 供電不足 | 伺服馬達 V+ 需外接 XL4015 降壓模組 5V 輸出，不能從 ESP32-C3 的 3.3V pin 取電 |
| 伺服回應但角度不對 | 歸位值需校正 | 調整 `SHOULDER_HOME`、`ELBOW_HOME` 等常數 |

### 機構相關

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| 走路時卡死 | 曲柄相位錯誤 / 螺絲太緊 | 確認同側每足相位差 90°、左右錯開 180°、鬆開螺絲加尼龍墊圈 |
| 足端軌跡異常 | 連桿比例不對 | 參考 `TheoJansen連桿設計參考.md` 重新檢查連桿尺寸 |
| 機器人翻倒 | 手臂太重 / 重心偏移 | 加配重或降低手臂安裝位置 |
| 夾爪夾不住零件 | 扭力不足 / 角度不夠 | 調整 `CLAW_OPEN/CLAW_CLOSE` 值或換更大扭力伺服 |

### 電源相關

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| ESP32 不開機 | 電壓不夠 | 確認電池電壓正常，用三用電表量測 |
| LED 快速閃爍 | 電池電壓過低（< 9.6V） | **立即停止使用，充電！** |
| LED 慢速閃爍 | 電池電壓偏低（< 10.0V） | 可繼續使用但應盡快充電 |
| 突然斷電 | 電池保護板斷電 | 電池電壓過低觸發保護，充電後恢復 |

## 🚚 運輸機器人（EV3）

### 循跡相關

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| 車子完全不跟線 | 感測器高度太高 | 調整離地 5~10mm |
| 嚴重左右晃動 | KP 太大 | 降低 `KP`，先從 0.5 開始調 |
| 晃動不收斂（越晃越大） | KD 不夠 | 增加 `KD` 值 |
| 慢慢偏離 | KI 不夠 | 微調增加 `KI`，但不要太大 |
| 速度太快失控 | BASE_SPEED 太高 | 降低 `BASE_SPEED`，穩定後再加 |

### 顏色偵測相關

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| 黃色/紅色偵測不到 | 感測器離地太高 / 光線干擾 | 降低感測器高度、避免強光直射 |
| 錯誤觸發停止 | 地面反光 / 顏色相近 | 使用更鮮豔的色紙、加深顏色對比 |
| 偵測到但沒停車 | 程式邏輯問題 | 在 `check_stop_color()` 加 `print` 除錯 |

### EV3 連線相關

| 症狀 | 可能原因 | 解決方法 |
|------|---------|---------|
| EV3 開不了機 | 電池沒電 | 充電或更換 AA 電池 |
| 電腦連不到 EV3 | microSD 卡問題 | 確認已安裝 Pybricks OS、USB 線正常 |
| 程式上傳失敗 | VS Code 擴充問題 | 重新安裝 EV3 MicroPython 擴充 |
| 螢幕顯示 "ERROR!" | 程式執行異常 | 查看螢幕上的錯誤訊息，對照程式碼除錯 |
| 螢幕顯示 "Timeout!" | 循跡逾時 | 檢查軌跡線是否完整、感測器是否偏移 |

## ⚡ 快速排查流程

遇到問題時，按照以下順序快速排查：

```
1. 電源正常嗎？
   └─ 沒電 → 充電 / 換電池

2. 接線正確嗎？
   └─ 鬆了 → 重新插好、對照接線圖

3. 程式有上傳成功嗎？
   └─ 沒有 → 重新上傳

4. Serial Monitor 有輸出嗎？
   └─ 有 → 看 CMD 是否正確收到指令
   └─ 沒有 → 檢查 Serial 鮑率

5. 單獨測試子系統
   └─ 馬達、藍芽、伺服分開測
```

## ⚡ 電源系統深度排查

### 降壓模組問題

| 症狀 | 可能原因 | 排查步驟 |
|------|---------|---------|
| XL4015 輸出不穩（5V 上下跳動） | 輸出端電容未裝 / 容量不足 | 確認 1000μF + 100nF 已焊好，電容極性正確 |
| XL4015 輸出 < 4.5V（負載時） | Servo 同時動作電流過大 | 避免 3 顆 Servo 同時堵轉，改為依序操作 |
| LM2596 輸出偏移 | 電池電壓下降後校準偏移 | 帶負載狀態下重新校準至 5.0V |
| 降壓模組非常燙 | 輸入輸出壓差大 + 負載電流大 | 確保通風，考慮加裝小散熱片 |

### Servo 突波導致 MCU 重啟

**症狀**：Servo 動作瞬間 ESP32-C3 重啟（Serial 重新顯示 boot 訊息）

**原因**：Servo 啟動瞬間電流達穩態 3-5 倍，若 Servo 電源與 MCU 電源共用或共地不良，電壓瞬間跌落導致 MCU Brownout Reset

**解決**：
1. ✅ Servo 電源（XL4015）與 MCU 電源（LM2596）必須分開
2. ✅ XL4015 輸出端必須有 1000μF 電容
3. ✅ 共地使用端子台星形連接，不要菊花鏈
4. ✅ 確認 Servo V+ 沒有誤接到 LM2596

### 電池電壓量測

用三用電表量以下位置：

| 量測點 | 正常範圍 | 異常處理 |
|-------|---------|---------|
| 電池盒正負極 | 14.0~16.8V | < 12V → 立即充電 |
| L298N 12V 端子 | 與電池盒相同 | 差 > 0.5V → 檢查接線鬆動 |
| XL4015 輸出 | 4.9~5.1V | 偏離 → 重新校準電位器 |
| LM2596 輸出 | 4.9~5.1V | 偏離 → 重新校準 |
| C3 5V pin | 4.8~5.1V | < 4.5V → 檢查 LM2596 到 C3 線路 |

### 共地問題排查

**症狀**：馬達偶爾不受控、Servo 抖動、ESP-NOW 時斷時續

**排查**：
1. 用三用電表**通斷檔**，量測任意兩個 GND 點之間是否導通
2. 特別檢查：電池 GND ↔ L298N GND ↔ XL4015 GND ↔ LM2596 GND ↔ C3 GND ↔ Servo GND
3. 如有不通：找出斷點，補接線或改用端子台集中

## 📡 ESP-NOW 通訊深度排查

| 症狀 | 排查重點 | 解法 |
|------|---------|------|
| `Failed to add peer` | MAC 地址格式 | 確認 `{0x58, 0x8C, ...}` 格式，6 byte |
| `ESP-NOW -> Leg: FAIL` | 子控板未上電 / channel 不同 | 確認子控板已上電、`ESPNOW_CHANNEL = 1` |
| 主控顯示 OK 但子控沒收到 | MAC 填錯 | 重新上傳 `00_macaddress` 核對 MAC |
| 收到指令但馬達不動 | enum 不一致 | 比對 protocol.h 與各 .ino 的 enum 定義 |
| 偶爾封包遺失 | 距離太遠 / 干擾 | 在 1m 內測試；遠離 WiFi 路由器 |
| ACK 收不到 | C3 #1/#3 沒有 ACK 實作 | 目前只有 C3 #2 回傳 ACK |
| 主控板加入 Peer 後卡住 | BLE 和 ESP-NOW 衝突 | 確認 WiFi.mode(WIFI_STA) 在 BLE init 之前 |

### Channel 不匹配排查

ESP-NOW 要求收發雙方在同一 WiFi channel。所有控制板必須設定：
```cpp
const uint8_t ESPNOW_CHANNEL = 1;  // 必須一致
esp_wifi_set_channel(ESPNOW_CHANNEL, WIFI_SECOND_CHAN_NONE);
```

排查方式：在主控和子控的 `setup()` 中加入：
```cpp
uint8_t primaryChan;
wifi_second_chan_t secondChan;
esp_wifi_get_channel(&primaryChan, &secondChan);
Serial.print("WiFi Channel: "); Serial.println(primaryChan);
```

## 🔌 BTS7960 驅動深度排查（腿部 + 大圓盤）

| 症狀 | 可能原因 | 解法 |
|------|---------|------|
| 馬達完全不轉 | **R_EN/L_EN 未接 3.3V** | 確認 R_EN/L_EN 已接 C3 的 3.3V pin 或跳線 |
| 馬達只有一個方向轉 | RPWM/LPWM 其中一個接線鬆| 重新插好杜邦線 |
| 馬達轉但扭力很小 | PWM duty cycle 太低 | 調高 `dutyCycle`（最低約 80 才能啟動） |
| 馬達速度無法調整 | RPWM/LPWM 未正確接到 PWM GPIO | 確認接線對應程式中的 GPIO 定義 |
| BTS7960 非常燙（>60°C） | 馬達堵轉 / 電流過大 | BTS7960 有過溫保護，檢查馬達是否卡死 |
| B+/B- 反接 | 電源極性接反 | **立即斷電！** 檢查是否損壞，修正接線 |
| PWM 調速顯粒感很重 | PWM 頻率太低 | 確認 `pwmFreq = 20000`（20kHz） |
| 兩馬達速度明顯不同 | 馬達個體差異 | 在程式中加左右速度補償常數 |

### PWM 設定確認（BTS7960）

```cpp
// BTS7960 控制原理：
// 正轉：RPWM = PWM duty, LPWM = 0
// 反轉：RPWM = 0, LPWM = PWM duty
// 停止：RPWM = 0, LPWM = 0

const int pwmFreq = 20000;        // 20kHz，BTS7960 最佳範圍
const int pwmResolution = 8;      // 0~255
ledcAttachChannel(motorL_RPWM, pwmFreq, pwmResolution, pwmCh_L_RPWM);
```

> 如果 PWM 頻率 < 15kHz，馬達可能發出明顯的嗡嗡聲。

| 症狀 | 可能原因 | 解法 |
|------|---------|------|

## 🔧 Servo 深度排查

### 360° 連續旋轉 Servo 問題

| 症狀 | 原因 | 解法 |
|------|------|------|
| `write(90)` 仍微轉 | 零點偏移（每顆不同） | 修改 `R_STOP` 為 88~92，逐 1 測試 |
| 轉速不均（正轉快反轉慢） | Servo 個體差異 | 在程式中分別設定正反轉速度 |
| 完全不轉 | 信號線未接 / 供電不足 | 確認 GPIO → 信號線、XL4015 → V+ |
| 轉一下就停 | 限位開關誤觸發 | 輸入 `?` 查看限位狀態 |

### 180° 標準 Servo 問題

| 症狀 | 原因 | 解法 |
|------|------|------|
| 持續抖動 | 供電不足或信號雜訊 | 確認 XL4015 電容、共地良好 |
| 不轉但有嗡嗡聲 | 電壓 < 4.5V | 量測 V+ 電壓，重新校準 XL4015 |
| 角度不準 | Servo 個體差異 | 調整 `CLAW_OPEN_ANGLE`/`CLAW_CLOSE_ANGLE` |
| Servo 過熱 | 長時間施加外力 | 減少夾持時間，選合適角度讓 Servo 不出力 |

### ESP32Servo Library 注意

- ESP32Servo 使用 LEDC 硬體計時器，與 `ledcAttachChannel()` 共用
- C3 #3 只用 Servo（不用 L298N），不會衝突
- 如果同一塊 C3 要同時用 `ledcWrite()` 和 `Servo.write()`，需注意計時器通道分配
